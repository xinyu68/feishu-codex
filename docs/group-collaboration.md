# 群聊角色协作

在同一个飞书群里添加多个机器人，分别承担产品、开发、测试等角色。每个机器人在这个群里使用独立的 Codex 会话，你通过手动 @决定谁执行工作。

## 配置

1. 为每个机器人创建一个独立的飞书自建应用，开启机器人能力、长连接和 `im.message.receive_v1`。卡片交互使用 `card.action.trigger`。基础步骤见 [配置指南](getting-started.md)。同一个 App ID 只能配置一次。
2. 在开放平台为每个应用开通“接收群聊中 @机器人消息”（`im:message.group_at_msg:readonly`）及发送消息权限，并发布版本。
3. 在本应用“机器人”页面添加机器人，填写名称、App ID 和 App Secret；验证后自动连接，并进入“访问权限”。在“对话设置”中填写群聊角色说明、选择模型与推理强度，留空沿用本机 Codex 配置。
4. 将机器人添加到同一个飞书群，分别 @它们发一条消息。
5. 在左侧选择对应机器人，在“访问权限”中分别允许自己的账号和这个群，然后重新 @发送消息。群聊授权不会自动授权群成员，一个机器人的授权也不会自动复制给其他机器人。
6. `@机器人 /project` 选择本机项目，随后发送工作要求。第一次工作会创建专属角色会话。

引用平台消息需要具备读取对应消息的权限。希望普通群聊发言也成为背景时，需要额外开通获取群内用户消息的权限；以开放平台 [接收消息](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive) 和 [获取指定消息](https://open.feishu.cn/document/server-docs/im-v1/message/get) 的当前权限要求为准。未开通时仍可使用已接收的 @消息及本应用机器人发布的结果进行协作。

## 如何使用

```text
@产品经理 设计登录流程，列出验收标准
@开发 按上面的方案实现
@测试 根据需求检查开发结果
```

引用具体方案消息再 @目标机器人，交接内容更明确。多个方案有歧义时，机器人应先澄清。

- 没有 @时不主动回答；上一条 @过，也不表示后续消息自动触发。
- 同时 @多个机器人，每个被 @的机器人各自收到一次要求。
- 普通提及只进入公共背景；机器人在最终回复末尾明确交接时，桥接可以安排另一角色继续，规则见下方“机器人交接”。
- 背景只包含该群当前项目的有限近期公开消息和明确引用，不复制其他角色的完整历史、工具日志或私聊。长方案可引用原消息，或使用项目中的文档。
- 同一个本机项目的群聊任务会排队，避免不同角色同时修改文件。当前同一角色会话的补充消息仍可加入正在处理的任务；`/stop` 可以取消等待。

## 项目与会话

一个群共用一个项目。通过任一机器人切换群项目，会为群里各角色准备该项目的新会话；有任务运行时需先等待结束。不同机器人拥有各自的 `/new`、`/session`、模型和推理强度。

群里的 `/session` 只展示当前机器人在这个群创建或使用过的专属会话。这样可以保持角色和历史归属清楚。可以在 Codex 桌面打开这些会话继续工作，之后再次 @对应机器人接着处理。

在“机器人 → 对话设置”中可分别填写群聊和私聊角色说明。群聊沿用已配置的机器人角色；私聊说明默认留空，按普通 Codex 使用，不继承群聊角色或机器人名称。需要固定的个人助手职责时，可以选填独立的私聊说明。模型与推理强度仍由同一个机器人配置。

角色说明在创建会话时固定。编辑或清空说明后，请在对应的私聊或群聊中使用 `/new` 新建会话；已有会话保留原角色，在桌面继续也保持一致。升级前已带角色的私聊不会自动清除角色；要按普通 Codex 使用，请保持私聊说明为空并新建会话。从桌面选择的既有会话也不会被强加新的机器人角色。

升级机器人交接功能时，应用会为自己管理的空闲群会话补充协作说明，保留原角色、会话 ID 和历史。

固定回复规则和 Skill 指引通过独立应用上下文提供；用户消息首行只保留 `【飞书消息】` 或 `【本地预览】`，同时兼容带完整说明的旧版消息头。渠道按当前消息判断，历史、引用和代码中的标记不算本轮来源；桌面续聊没有标记时，不会仅因会话过去来自飞书就自行转发普通回复。

群任务排队只协调本应用提交的群聊任务。直接在桌面操作多个会话时，仍应避免同时修改同一份文件。

## 机器人交接

可以直接安排团队任务，例如：

```text
@产品经理 设计一个待办小工具，然后交给开发人员复述方案；这次只讨论，不修改代码。
```

应用自带的 `feishu-codex` Skill 说明固定协作规则和交接格式。每条消息只附带当前可用角色；自动交接另外附带来源角色、交接次数和原始任务，减少重复说明。它可以在最终回复末尾用独立一行明确下一步：

```text
交接给 @开发人员：复述上面的三个功能，说明实现顺序，不要修改代码。
```

桥接确认回复送达后，把交接任务、原用户要求和公开群聊背景交给目标角色自己的 Codex 会话。卡片中的普通 `@名称` 不等于派发；代码示例、引用、随口提及、自己 @自己和无法区分的名称不会自动执行。每次只能指定一个目标。

同一回复重复交接给同一个角色时，只执行最后一条明确任务。目标角色已经收到你的消息、正在处理或排队时，不重复派发；排队任务开始时会读取最新群聊背景。同一轮追加要求后，完成回复以最后一版回答为准。

- 两端机器人、操作者和群均须授权并已连接。跨应用账号只按飞书提供的身份信息或同一条真实消息关联，不按姓名或授权名单猜测。首次使用可同时 @两位机器人发送“协作测试”，建立账号关联。
- 一个用户任务最多自动交接 6 次，超过后提示暂停。需要继续时由你手动 @指定角色。
- 你再次 @下达新要求，旧任务不再继续接力；不 @的普通群发言仍只是背景。
- 向参与的任一机器人发送 `/stop`，可停止自己发起的本群接力。进度卡片的停止按钮只作用于它对应的任务，旧卡片不会停止新任务。
- 目标角色正在桌面执行其他任务时，自动交接不会混入该任务，会明确提示稍后手动继续。
- 失败、中断、授权撤销、切换项目/会话、回复送达不确定或服务退出时，不继续自动接力，不自动重放未确认的指令。

机器人间的消息仍由现有桥接内部传递，无需新增消息接收服务。

## 通知与审批

工作结果、附件和审批沿用本轮的机器人和群聊。审批只能由原请求账号在原聊天处理，或在本机管理页处理。桌面继续旧的角色会话，即使飞书已 `/new`，已知来源的完成通知也仍发往原机器人和原群；不会自动切换当前会话。

桌面任务没有明确群绑定时，不自动猜一个群发送。只有唯一已授权私聊时，才沿用私聊通知默认目标。机器人离线时，尚未发送的完成通知保持等待；不会把同一通知广播到所有机器人。

## 本地验收

1. 群内不 @，确认没有机器人回答；分别 @两个机器人，确认身份和会话独立。
2. 产品机器人输出方案，引用它并 @开发，确认开发能识别方案。
3. 对其中一个机器人 `/new`，确认另一个的会话不变。
4. 桌面打开角色会话继续一轮，再从飞书接着问，确认历史连续。
5. 同项目同时向不同机器人提要求，确认等待及停止等待有效。
6. 撤销其中一个机器人对群的授权，确认它不能继续执行，其他机器人仍正常。

本功能参考了 [cc-connect](https://github.com/chenhg5/cc-connect) 的精确 @识别、引用消息和群聊公共上下文设计。

## 群聊上下文如何传递

每个机器人保留自己的 Codex 会话历史。桥接按机器人、群、项目和 Codex 会话保存已送达记录，同一会话只补充还没收到的公开群消息，不再每轮重复附加整个近期记录。当前用户消息和该会话自己的回复不会作为背景再次发送；用户明确引用的消息会单独附带一次。

群聊背景、明确引用和交接信息仍随当前用户消息传入，不迁入固定应用规则，也不因此获得新的操作授权。送达核验继续使用包含本次群资料和唯一批次的原始输入。

首次进入新会话从最近 20 条公开记录中选取背景，受每次 16000 字符预算限制。长消息分段传递，未送达的部分仍可在后续补充。桥接本机每群最多保留 100 条记录，群数量和总文本量也有限制，因此这不是完整群聊归档。需要指定旧方案时，请直接引用它。

送达记录在 Codex 确认接收后才保存。提交失败不会提前跳过背景；接收状态不明时，后续只读核对会话原始输入，确认匹配才记为已送达，不自动重发原用户任务。服务重启或切回原会话仍沿用记录；切到新会话则独立初始化。升级前没有送达记录的会话首次会补充一次近期背景，之后按增量处理。

Codex 原有上下文管理、压缩和桌面接续保持不变。本机制减少重复注入，不会删除既有会话历史，也不会自动把所有群记录传给每个机器人。

群聊参考资料使用“本机时间 · 发言人”和分行引用展示，不再重复包裹 JSON 字段。未知姓名以稳定的群友简称区分；存储和授权仍使用原账号标识。内部批次缩短显示，送达核验仍沿用原始输入哈希。


## 选择是否补充群聊背景

在“机器人”页面左侧选择机器人，在“对话设置”中设置“补充群聊背景”。每个机器人独立保存，默认开启，修改后自动保存并对后续提交生效。

- 开启：按现有增量机制补充已接收、已授权的同群当前项目讨论。
- 关闭：停止自动补充群记录，保留当前 @该机器人的任务、明确引用和交接内容。该机器人的 Codex 会话历史继续保留，无需新建会话。
- 同群其他机器人的设置、群消息收集和回复触发规则不受影响；没有 @仍不会主动回复。
- 重新开启沿用原送达记录，只补充本机仍保留且尚未传入的背景，不保证补齐关闭期间的全部消息。

关闭后若要使用另一位机器人的方案，请引用那条方案再 @目标机器人，或明确交接。切换开关不会删除已进入 Codex 的历史。
