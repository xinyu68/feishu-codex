# 使用帮助

## 桌面和飞书如何接续

先打开 Feishu Codex，再让它自动打开 Codex，或点击“打开 Codex”。桌面和飞书接着同一条线程操作，沿用本机项目与历史。

飞书通过 `/project`、`/session` 明确选择当前目标；本地工作台与这个选择同步。官方桌面只是切换标签时，不会自动改绑飞书的会话。

群里发送 `@机器人 /new`，会新建该机器人的会话，并从此刻重新积累群聊背景。也可同时 @多个机器人发送 `/new`、`/status`、`/stop` 或 `/session`，分别新建会话、查看状态、停止任务或列出各自的会话。选择旧会话时，仍需在对应机器人的卡片上操作。旧讨论不再自动带入新会话；主动引用和明确交接仍可使用指定的旧内容。未被 @的机器人不受影响。

群里通过 `/session`、本地工作台或通知卡片成功切换到不同的旧会话时，会保留原会话的历史、角色和会话 ID，并从切换成功时重新积累群聊背景，跳过离开期间的群聊。仅查看会话列表、重复选择当前会话或切换失败不会重置起点。Codex 和 Hermes 均遵循此规则；主动引用和明确交接仍可带入指定的旧内容，其他机器人的上下文不受影响。服务重启后继续使用当前保存的起点。

切换会话不会取消旧任务。执行期间继续发送消息会补充当前轮次，`/stop` 停止当前选择的任务。遇到连接中断或发送结果不确定时，先看历史，避免重复提交。

## 处理进度与完成通知

**“在飞书显示处理进度”默认开启**。Codex 发出第一条中途说明时立即显示临时进度卡，后续说明更新同一张卡。没有中途说明时只显示处理中表情，任务结束后发送结果，不按耗时创建占位卡。可在“设置 → 对话与通知”中关闭，应用会记住你的选择。

飞书任务已有进度卡时，结束后直接把原卡更新成完整结果，移除停止按钮，不撤回、不重复发结果卡。没有进度卡时正常发送一条结果；长答案续篇和图片仍单独发送。

确认结果送达后，机器人移除原消息上的敲键盘表情，添加并保留“完成”表情。同一轮补充输入共用结果卡和一次完成提醒。失败、停止或结果送达未确认时会展示相应状态，不标记“完成”；表情添加失败不影响已保留的结果，也不会重复发送答案。

短暂网络故障时，回复会使用同一个去重编号有限重试，卡片更新和处理表情清理也会重试。持续失败时，结果仍保存在本机工作台；发送 `/status` 可分别查看执行状态与最近回复的送达状态。“空闲”只表示当前没有任务执行，不代表回复已经送达。送达未确认时先查看本轮结果，不要重复提交原任务。

桌面任务有两种方式：

- 临时要求：在任务中说“完成后飞书通知我”，Codex 通过内置 MCP 登记这一轮的通知。
- 自动通知：默认开启，仅通知耗时超过 1 分钟的桌面任务。可在“设置 → 对话与通知”调整时长、改为每轮通知或关闭。

在“机器人”页面点击“设为默认通知机器人”，未绑定飞书的桌面会话会通过它发送自动或按需完成通知。已有会话绑定优先，切换默认机器人不会切换当前会话或开启自动通知。首次完成私聊授权、且只有一个可用私聊时会自动设为默认；后续添加机器人不会改变这个选择。同一个机器人有多个私聊账号时，需要先选择接收人；也可以取消默认。默认接收位置失效后会提示重新设置，不会转发给其他机器人。

显式请求的通知不受长任务阈值限制，同一轮会合并重复的通知来源。通知卡片包含项目、会话、结果和“切换到此会话”按钮；只有点击按钮才会切换目标。

原 Codex 图标启动的独立模式不在通知范围内。电脑睡眠、网络离线、飞书免打扰或系统通知限制都可能影响到达时间和手机提醒。

## Skill、MCP 与文件

应用自动安装 `feishu-codex` Skill，并在托管的 Codex 运行实例中配置 `feishu_completion` MCP。

- Skill：解释渠道来源、回复规则和工具用法。
- `request_feishu_completion_notification`：登记本轮结束后发送通知。
- `send_artifact_to_feishu`：Codex 和 Hermes 均可按明确要求发送指定的本地图片或文件，发回任务所在的私聊或群聊。Hermes 在本轮结束后发送；工具显示“已提交”时尚未确认送达，以飞书中的实际发送结果为准。
- `send_message_to_feishu`：按明确要求立即发送文字到默认通知私聊，Codex 和 Hermes 均可调用，不需要结束当前任务。发送位置使用“机器人”页面的默认通知设置，与当前会话绑定和自动完成通知开关独立；不会切换会话。
- `request_feishu_group_handoff`：在已授权的飞书群任务中，申请让另一角色接手；当前回复送达并结束后才派发。详见[群聊协作](group-collaboration.md)。
- `consult_feishu_group_agent`：在当前飞书群轮中委派另一角色完成任务，可以查询、改文件、执行命令和操作外部应用，按用户授权使用现有工具。桥接公开任务并 @目标，再以目标身份展示进度和结果，同时将结果返回来源机器人，让它在同一轮继续。Codex 和 Hermes 均支持，单次最多等待 30 分钟；目标使用可接续的专用协作会话，普通群会话绑定保持不变。

连接机器人后即可使用这些内置能力。

例如可以说“先把目前的调查结论发到我的飞书，再继续检查”。即时消息工具复用应用已有机器人，无需安装飞书 CLI。普通飞书回复仍由桥接自动转发；内置 Skill 会避免对同一发送请求同时调用 MCP 和 CLI。工具通过唯一请求编号防止重复提交，确认发送后才返回成功；结果不明时应先核对，不换工具补发。

例如在群里要求“先问测试角色这个方案有哪些风险，再综合回答我”。正常流程是先看到发起机器人公开问题并 @测试机器人，再看到测试机器人的回答，最后由发起机器人继续给出自己的结论；后者不重复转发整份咨询答案。公开问题只使用本次 `question`，补充 `context`、咨询票据和完整会话历史不会随问题发布。

咨询进度遵循“在飞书显示处理进度”设置；进度只来自真实中途说明，没有说明时不创建占位进度，也不公开内部推理或工具日志。关闭进度显示时，公开问题与最终答案仍会展示。群内展示由桥接负责，模型不额外发送问题、答案或登记通知。真实 @用来展示咨询对象，派发仍走内部 MCP 流程，不依赖机器人群消息触发，也不另启接收器。

机器人使用当前轮桥接提供的咨询票据和角色名单，每轮最多顺序咨询 3 次；连续咨询时依次展示问题、答案、下一问题、下一答案，最后由来源机器人给出结论。私聊、本地预览和桌面续聊没有票据，不能借用历史群绑定发起咨询。无法确认目标的真实 @身份，或公开问题发送失败、送达未确认时，不会启动目标咨询。咨询失败或答案送达未确认会如实说明，取得分析结果不等于群内发布成功，不自动重试或改用交接、其他接口补发。同步协作也可委派修改文件、执行命令和外部应用操作，按用户授权使用现有工具；审批或问题由目标机器人转回原群。不等待结果、让对方接手继续时使用交接。详见[同步咨询](group-collaboration.md#群内同步咨询)。

普通编码任务不会自动上传源码。需要成品时明确说明“把这张图发到飞书”或指定文件路径。一次最多 5 个文件，图片上限 10 MB，其他文件上限 30 MB；飞书向机器人发送的附件上限为 20 MB。

## 运行与退出

- 安装版会检查 GitHub 上的新版本；在“设置 → 应用与运行”可手动检查、下载并确认安装。安装前会检查正在运行的任务，不能安全退出时保留当前版本，稍后再试。
- 默认关闭窗口后保留在托盘，可改为退出全部服务。
- Windows 开机启动默认关闭，可在“设置 → 应用与运行”开启。
- 已打开独立 Codex 时，点击“连接飞书”并确认重启即可接入；这会终止运行中的任务。
- 应用退出、升级、卸载会检查任务与进程归属，避免误关其他程序。
- 修改模型、强度和偏好后自动保存。首次设置飞书凭据时先验证再连接。

## 常见问题

| 现象 | 检查方向 |
| --- | --- |
| 已连接但机器人不回复 | 是否发布应用、订阅接收消息事件、允许当前账号；是否有其他服务接收同一机器人的事件 |
| 卡片按钮无反应 | 是否启用 `card.action.trigger` 回调，并发布最新配置 |
| “Codex 已打开，但尚未连接飞书” | 桌面独立运行；通过工作台确认“连接飞书” |
| 会话在另一个应用中打开 | 检查是否有其他 Codex / CLI 进程正在使用它；不要删除会话记录或锁文件 |
| 收到结果但手机没提醒 | 检查飞书多端通知、免打扰和系统通知权限；结果确认送达后会在原消息添加“完成”表情，实际提醒由飞书决定 |
| `/usage` 无可用余量 | 取决于 Codex 登录类型；API Key 等登录方式可能没有 ChatGPT 套餐额度 |
| 更换模型服务后不能执行任务 | 先确认同样的模型配置在本机 Codex 可用 |
| 卸载重装后需要恢复配置 | 保留应用数据时可恢复；清除数据后需要重新填写凭据并授权账号 |

问题反馈请附应用版本、Codex 版本、复现步骤和脱敏日志，见 [Issue 模板](https://github.com/xinyu68/feishu-codex/issues/new/choose)。
