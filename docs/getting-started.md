# 安装与飞书配置

## 准备

- Windows x64，已安装并登录官方 Codex，能够在桌面正常开始任务。
- 一个可创建自建应用的飞书账号；组织策略可能要求管理员审批权限和发布。
- 本机能够连接飞书和你使用的 Codex 模型服务。

在 [Releases](https://github.com/xinyu68/feishu-codex/releases/latest) 下载最新的 `Feishu-Codex-版本号-Setup.exe`，双击安装。安装时选择父目录，向导会补上 `Feishu Codex` 文件夹，并显示最终安装路径。

## 1. 创建飞书机器人

打开 [飞书开放平台](https://open.feishu.cn/app)，创建企业自建应用，添加 **机器人** 能力。在“凭证与基础信息”获取 App ID 和 App Secret。

密钥只填到本机应用中，不要写入代码、Issue 或公开截图。为 Feishu Codex 使用独立的飞书应用，避免与其他 Agent 争抢消息事件。

## 2. 开通应用权限

在“权限管理”按实际功能开通应用身份权限。收发消息、更新卡片、图片文件和表情反馈需要相应权限；飞书后台会在配置事件和调用 API 时提示缺失项。

| 功能 | 权限标识 |
| --- | --- |
| 接收用户发给机器人的单聊消息 | `im:message.p2p_msg:readonly` |
| 机器人发送消息 | `im:message:send_as_bot` |
| 更新已发送的进度卡片 | `im:message:update` |
| 获取、上传图片或文件资源 | `im:resource` |
| 添加和移除处理中的表情回复 | `im:message.reactions:write_only` |

以开放平台当前显示的权限要求为准，相关接口见 [接收消息](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive)、[发送消息](https://open.feishu.cn/document/server-docs/im-v1/message/create)、[添加表情回复](https://open.feishu.cn/document/server-docs/im-v1/message-reaction/create)。

## 3. 连接应用并订阅事件

1. 打开 Feishu Codex，首次点击“开始设置”，进入“机器人 → 连接设置”。
2. 填入 App ID 和 App Secret。两项填齐并离开输入区域后，应用先验证凭据，再保存并自动连接。
3. 回到飞书开放平台“事件与回调”，选择 **使用长连接接收事件**。如果平台提示尚未建立连接，先确认本机应用运行且凭据验证成功。
4. 在事件配置中添加 **接收消息 v2.0**：`im.message.receive_v1`。
5. 在回调配置中启用 **卡片回传交互**：`card.action.trigger`，使用长连接接收回调，使项目选择、会话切换等按钮生效。
6. 创建并发布应用版本，设置可用范围，按组织要求完成审批。

长连接不需要公网服务器、域名或端口映射。同一机器人只运行一个事件接收服务。

## 4. 授权你的账号

在飞书中找到机器人并私聊发送一条消息。对应机器人的“访问权限”中出现待授权账号后，允许你自己的账号，再回飞书发送 `/project`。

“Access denied”说明机器人收到了消息，但本机授权名单还没有允许这个账号。不要为了绕过该提示允许未知账号。

## 5. 接着桌面的工作

应用默认同时打开 Codex；也可以点击工作台的“打开 Codex”。在飞书发送 `/project` 选择项目，再通过 `/session` 选择希望继续的会话。

第一个机器人完成私聊授权后，只有一个可用私聊时会自动设为默认通知机器人。之后可在“机器人”页面更换或取消默认；添加其他机器人不会改变已选默认。未绑定飞书的桌面会话通过默认机器人发送完成通知，已有会话绑定仍然优先。

如果原版 Codex 已独立打开，应用会暂停飞书写入并提示“连接飞书”。点击后确认重启；运行中的任务会停止，已保存的历史保留。之后桌面与飞书连接到同一运行实例。

## 数据与卸载

本应用数据默认位于 `%USERPROFILE%\.feishu-codex`。日志在其中的 `desktop` 子目录，可通过应用“查看日志”打开。

卸载向导可勾选“清除本应用数据”，清除飞书凭据、账号授权、绑定、偏好、收发附件、临时配置、机器人迁移记录、Hermes 运行配置、日志和缓存。默认保留这些数据以便重装。正式卸载时，无论是否勾选，都会清理本应用安装且未经修改的 Codex、Hermes 内置 Skill，以及指向本次安装的 Hermes MCP 配置。覆盖升级不会执行这项清理。

Codex 和 Hermes 的账号、会话历史、个人 Skills、其他 MCP、模型配置及项目文件均保留。用户修改过的 Skill、角色文件或 MCP 配置会保留并记录在卸载详情中；此前备份的 Skill 也保留，不会随卸载删除。

退出或卸载前请结束任务。遇到阻止提示时查看状态和日志，不要通过删除 Codex 历史或锁文件来绕过。
